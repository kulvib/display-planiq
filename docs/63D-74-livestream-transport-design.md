# 63D-74 — continuous Livestream transport (implementation plan; not deployed)
Baseline: main 2d7f99aa4d471499b4938cc562a7e3f57cf7cd76, physical Viborg1 release 1248 with temporary uploader and RDP overlays. 73F test B: 7/7 PASS with one-second HLS configuration. Two simultaneous changes (73F resume + shorter segments); no isolated A/B attribution. Release 1249 held.

## Transport decisions and limits
- Keep the existing viewer heartbeat and leave, server generation authority, explicit stop, per-product permissions and 30-second desktop warm-tab rule. Mobile timed viewer behavior remains unchanged. RDP has no dependency on Livestream.
- Existing producer: Mutter PipeWire -> x264enc -> h264parse -> mpegtsmux -> hlssink. Design one encode with bounded leaky branches, not two capture/encode sessions. Continuous WSS candidate: fMP4 (init + independently recoverable fragments) using GStreamer fragmented MP4 output and browser MSE. Validate actual fragment boundaries, codec and keyframe availability on installed Ubuntu before choosing pipeline. HTTPS HLS remains working fallback. Keep 1s HLS as candidate configuration; audit every installation/default/upgrade path and actual generation readback before making permanent, preserve explicit operator overrides.
- Separate authenticated agent publish and browser subscribe endpoints, not the RDP relay and not the agent command-wake socket. Server owns current client/generation binding. No externally listening client port. Existing agent credentials are scoped; do not reuse a browser credential for publishing. Browser handshake: validate origin, short-lived purpose-bound single-use ticket via authenticated HTTPS, avoid URL/log credential leakage; close on parent session expiry/revocation or loss of viewer authorization. Never allow token renewal to recreate a healthy player. No payload logging. Validate generation on connection, close/discard on generation transitions; do not perform database reads per fragment.
- Versioned bounded binary framing: init/keyframe flag, generation, sequence, media timestamp; size/sequence limits before parsing. Server per-client latest init + bounded current independently decodable fragment window in memory, bounded per-viewer queues; on lag drop old data and resync at keyframe or close bounded slow connection, not block producer or other clients. Clear all buffers on generation close. No disk persistence for WSS, no per-frame DB writes. Limits to be derived from measured bitrate, active viewers, Render memory/CPU; 100 attached clients is not 100 simultaneous videos.
- Browser MSE support and codec check, bounded startup deadline, init then contiguous fresh fragments, purge obsolete media on discontinuity; visibility catch-up prioritizes newest safe decode point. WSS state only after actual playable media; HTTPS fallback on unsupported codec, missing publisher, timeouts, abnormal closure, or bounded resync failure. Single active player per view; cancel late callbacks with epoch, no concurrent fallback loops. Retry WSS with bounded backoff after stable fallback, no producer restart for transport switching. Existing HLS fallback must remain independently playable. Do not force permanent duplicate media traffic while no WSS subscriber; instrument demand and compare tradeoff with fast HLS failover.
- UI: actual active transport, shared displayed-tenth thresholds (0–7 green, >7–10 yellow, >10–15 orange, >15 red). Missing measurement neutral. HLS live-edge estimates are not end-to-end capture delay; WSS only uses comparable measured estimate, otherwise explicitly label metric/unknown. No threshold drives restart. Preserve existing layout and separate error/buffering/stopped overlays.
## Merge and release gates
- This draft implements shared latency presentation, null handling, an unregistered bounded relay core and matching browser wire decoder. No network endpoint, capture integration, browser MediaSource player, automatic transport fallback or permanent 1s default implemented yet. Do not promote as completed 63D-74.
- Next implementation must cover capture/runtime, relay and auth, browser both views, transport fallback and bounded resource limits together, with protocol negative tests and actual Chromium MediaSource playback. Verify authorization/tenant isolation, invalid lengths, stale generations, expiry, slow subscriber, disconnect/reconnect, producer stop, 30-second hidden and mobile stop, and independence from RDP. Verify signed packaging/migration and rollback on Viborg1.
- Physical WSS/HLS fallback tests with simultaneous RDP, deliberate WSS loss, actual latency and frame freshness, 5 min uninterrupted visible playback, short and long fan switches, CPU/memory/network baseline under increasing viewer load. No release 1249 approval until physical evidence and gates.

## Approved layout and protocol increment
- Preserve the physically accepted Control Room / Overview / Remote Desktop layout; replace only existing live status text and its severity colors, no relocated fields or controls. Keep the right-aligned transport chip.
- Protocol v1: 28-byte big-endian header (CFLS magic, version byte, kind byte, zero reserved u16, safe-integer u64 sequence, safe-integer u64 relative media timestamp in microseconds, u32 payload length). Init kind 1 with zero sequence/timestamp; complete independently decodable fragment kind 2 with positive sequence and strictly advancing media timestamp. Actual independently decodable fMP4 requires capture proof; header is not proof of media validity. Core binds to an identity-only epoch handle per authorized client/generation, not a bearer token.
- Draft core retains exactly init plus latest complete fragment per channel; initial read or sequence gap returns init plus latest with decoder-reset indication. Prototype limits: 16 simultaneous publishers, 128 KiB init, 2 MiB fragment and 32 MiB global retained wire bytes. These are pilot guards, not a scale guarantee; router must additionally bound subscribers, socket/in-flight bytes, send deadlines and authorization rechecks. No endpoint is enabled. Cross-language wire golden vector and negative decoder tests added; Python suite and full CI still pending at this commit.
